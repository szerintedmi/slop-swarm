# AGENTS.md

Token-cost probe for a small society of CLI agents. The original spec, `docs/plans/2026-10-10-tiny-society-token-probe.md`, gives the design and rationale but is no longer maintained; the current behaviour is in the code, `README.md` and this file.

- **Stack:** Bun + TypeScript for the controller; Svelte 5 / SvelteKit for the dashboard, compiled with Vite (also running on Bun). Dashboard startup automatically builds when sources change; `just ui-build` forces a build and `just ui-dev` starts read-only HMR. `just` is the entry point; every recipe calls `src/cli.ts`.
- **Verify:** run `just test` and `just typecheck` before you finish. `just preflight` needs Docker and the secrets.
- **Every feature: API → CLI → just → UI.** Each action is an endpoint of the HTTP API (`src/api.ts`) first, then a CLI command (`--json` for scripts), a `just` recipe and a dashboard control. Nothing exists only in the UI.
- **Map:**
  - `src/service.ts`: the controller service (`just serve`; `just up` starts it in the foreground): dashboard + API, one active run at a time, launches from the `controls` queue (`run_id NULL`), resumes an active run on restart and follows its wakes again; SIGTERM detaches (the run keeps going). `src/api.ts`: the HTTP API (endpoint list in its header); `src/api-client.ts`: the CLI's side (`SLOPSWARM_API`, else the local service via `data/service.json`). `src/launch.ts`: preparing a run and bringing its world up.
  - `src/controller/`: scheduler, wake, notification poller, budget and `/self` writer (`/self/pricing.yaml` is the run's price table cut to the agent's own models; costing uses the full table). It is the only DB writer; the CLI and dashboard go through the API (or, with no controller at all, only enqueue into `controls`). `wake.ts` runs every wake through the agent host (`prepare` → `startWake` → stdout by offset); `host-files.ts` mirrors session files and relay logs by offset and keeps the home backup (`data/worlds/<w>/agents/<n>/gens/<N>`, `current` link swapped last); `worlds.ts`: listing worlds, moving pre-world runs into them.
  - `src/runner/`: the runner on the agent host (`just runner`, or in-process for `just up`): agent dirs, wakes (`docker run -d` + `docker logs -f` into files, reattached by label after a restart), proxy, world relays, forge forwarders, hard timeout and watchdog. `src/host/agent-host.ts`: `AgentHost` and its HTTP client `RunnerHost`, keyed by world and agent (never a host path). `src/runner/protocol.ts`: wire types, runtime sync allowlist; `src/runner/snapshot.ts`: the home snapshot stream (not tar).
  - `src/config-db.ts`: presets, agent profiles and seed versions in the DB (validated on save; `config/` is the default set, `just config import|export`). `src/hostconfig.ts` + `config/host.yaml`: the agent host's allowlist, container and runner limits (deployed, not editable from the dashboard; pushed to the runner at every run start).
  - `src/log.ts`: structured JSON logs (OTel field names; `data/logs/*.jsonl`, `just logs`); the relay has its own copy of the format (`relayLogger` in `docker/search/relay.ts`, which can't import `src/`), served through the runner's log. `src/backup.ts`: DB and forge backups (the VPS). `src/public-forge.ts`: the public read-only forge proxy behind Caddy (§7). `deploy/`, `.github/workflows/deploy.yml`, `docs/deploy.md`: the VPS (`deploy/vps/bootstrap.sh` sets the box up once: Docker, Tailscale, deploy user, sshd lock; `deploy/slopswarm-deploy` is what CI runs).
  - `src/harnesses/`: one adapter per agent CLI, the *harness* (`claude`, `codex`, `pi` for OpenRouter models; agent YAML `harness:`). Not to be confused with an agent's runtime dir (mounted at `/runtime`), its CLI state. Fixture-tested in `test/fixtures/`.
  - `src/pricing/`: per-request USD from `config/pricing.yaml` (plus fetched OpenRouter list prices, frozen into the run).
  - `src/openrouter.ts`: OpenRouter catalogue (prices, pi's `models.json` entries) and the per-generation charged-cost cross-check. OpenRouter agents: `harness: pi`, `provider: openrouter`, `key_env` (default `OPEN_ROUTER_API_KEY`); keys go into containers by name only.
  - `src/docker.ts`, `src/proxy.ts`, `docker/`: the container and egress boundary.
  - `src/forge.ts`: a world's Forgejo (the agents' shared space; one per world, hostname from the world id): containers, accounts (tokens kept per world on the controller's side), agent login files (rewritten at every prepare), notification counts, the public URL.
  - `src/github.ts`: the agents' public outlet: one GitHub org and shared account, logged in per wake from `SWARM_GITHUB_TOKEN` in `.env` (never passed as container env).
  - `src/search.ts`, `docker/search/relay.ts`, `docker/websearch`: the web search relay (Exa) for agents with `search: relay`: one container per world on the agent host (started by the runner), on the internal + egress networks, per-wake tokens, its `search.jsonl` (mirrored to `data/worlds/<w>/relay/`) billed to the wake as `exa-search` request rows. `EXA_API_KEY` reaches only the relay; api.exa.ai stays off the proxy allowlist. The same container serves web fetch when the config has `webfetch:` (then every wake gets a token; `search: false` tokens can only fetch).
  - `src/webfetch.ts`, `docker/search/webfetch.ts`, `docker/webfetch`: every agent's GET-only downloads of public URLs through the relay (`webfetch:` in the swarm config); the SSRF guard is in `docker/search/webfetch.ts`.
  - `src/world.ts`: a run's world time and effective swarm budget, extensions included (`just extend`).
  - `src/dashboard/ui/`: SvelteKit routes/components; `src/dashboard/service.ts`: dashboard data and control queue; `src/dashboard/server.ts`: embedded Bun server. `src/report.ts`: read-only report.
- **Invariants:**
  - Cost is computed per API request; vendor totals are only a cross-check.
  - Never weaken the container flags or the egress allowlist without being asked. The forge container stays on the internal network only (no route out).
  - The controller starts every connection to the agent host; the runner holds no controller credentials (one shared bearer token). Secrets reach the runner only at `prepare`/`ensure-up` and stay in its memory; containers get them by name (`-e NAME`). Home syncs never carry logins or tokens (runtime sync allowlist: `projects/`, `sessions/`).
  - The public forge is read-only: GET/HEAD plus `POST …/git-upload-pack`, no `/user/*` (but avatars), `/admin*`, admin API or archives, no credentials passed; its domain (`PUBLIC_FORGE_DOMAIN`) only in the VPS env file.
  - Web fetch (added at the owner's request) goes through the relay only: keep it GET-only, public addresses only (every resolved address and every redirect hop checked, connection pinned to the vetted address), ports 80/443; never add its targets to the proxy allowlist.
  - Never print or commit secrets (`.env`, `secrets/`).
  - Committed fixtures must be scrubbed of identities, but keep their token counts.
- **Worktrees:** each has its own `./data` (`SLOPSWARM_DATA_DIR` to point elsewhere; the runner's dirs are `data/runner/`, `RUNNER_DATA_DIR`). Careful: a writable command (anything that opens the DB, `just worlds` included) migrates that data dir's DB schema, and `up`/`resume`/`dash` move pre-world runs into worlds; point a branch's experiments at its own data. The dashboard/API defaults to port 7777 and forges to `127.0.0.1:3300` up (one port per world); if either is taken, the next free port is used and printed (`PORT=` / `FORGE_PORT=` pick the starting port). After a run ends, `just up`/`smoke`/`resume` keep both up until Ctrl-C. The proxy has no host port. The egress proxy is shared; the agent image is tagged with the Dockerfile hash and built on demand (`SLOPSWARM_AGENT_IMAGE` = a registry digest instead). Tests must not touch the real data dir: compute paths at call time (`dataDir()`), not from `DATA_DIR` at import (Bun's test runner loads `.env`).
- **Docs:** don't update the original spec or finished plans. Record behaviour changes in `README.md` / this file (and code comments); give new work its own plan in `docs/plans/`. Once every item in a plan is done, move it to `docs/plans/_archive/` and mark it done in its header; carry any leftovers to an open plan.
- **Don't** run `claude` or `codex` with `--dangerously-*` flags on the host; only inside the agent container.
